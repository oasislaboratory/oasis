# Proposal: The Way of Oasis

Status: Founder review required. This document proposes changes; it does not override protected root intent.

## Founding thesis
Oasis is a laboratory for cultivating leverage through disciplined practice, study, invention, enterprise, and reinvestment. The Way is the path, not a claimed universal optimization formula. Leverage is discovered in concrete situations and improved through practice. Economic results test the institution's capabilities; revenue alone does not define its purpose.

## Proposed root objective
Cultivate Oasis's long-term capacity to discover, create, and apply leverage in the world, through verifiable research and economically productive action.

Preserve the existing minAgentSpendmaxAgentEarn concept as an operational measure of efficiency and economic leverage, not the institution's entire identity. Track absolute net value, revenue, spend, risk, knowledge, reliability, and reusable capabilities separately.

## Proposed organizational graph
Four first-level activity domains (not rigid departments):
1. laboratory/ — study, graph theory, Graph Lang, experiments, evaluation, and publications/textbook.
2. technology/ — build and maintain Graph Browser, graph agents, reusable runtimes, and developer tools.
3. enterprise/ — operate ventures and market experiments: Price Chain, intelligence services/marketplace exploration, and other validated opportunities.
4. institution/ — the Oasis OS objective DAG, authority, capital allocation, agent rounds, governance, and institutional learning.

Cross-cutting relations should eventually be modeled as typed graph edges, not forced into filesystem containment. Graph Lang is the representation; Graph Browser is the general graph interface; Oasis OS is a particular application. The current Git filesystem tree is a temporary backing implementation, not the ontology of the system.

## Migration without breaking working systems
- Keep existing graph-browser/mvp code and routes in place while it is being tested.
- Keep AGENTS.md, directives.md, and existing protected objective outcomes unchanged until the founder approves a specific diff.
- Add the four domains first as explanatory objectives or views, not by moving live code.
- Explicitly map old objectives: graph-browser -> technology; recursive-optimization -> institution; pmf -> enterprise. Graph Lang -> laboratory with technology implementation interfaces.
- Introduce a graph entry adapter between filesystem traversal and UI rendering. Later support sparse ordered-pair adjacency entries with typed, possibly multiple, recursive morphisms.
- Do not treat descriptive permission edges as security enforcement; validate scoped writes at the trusted boundary.

## Practice loop
Observe -> hypothesize -> intervene -> measure -> preserve evidence -> adapt.
Each active experiment should have an objective, prediction, cost/risk budget, evidence, and a next allocation decision. No venture should consume resources indefinitely without demonstrable earnings, learning, or a founder-approved strategic option.
