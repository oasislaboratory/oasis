## Hypothesis
A read-only graph-source boundary plus an explicit Oasis OS projection can preserve the filesystem objective browser while allowing identities and typed relationships that are not filesystem containment.

## Prediction (freeze before execution)
1. The filesystem adapter and objective projection produce deeply equal page models to Repository.node for root, child, leaf, and Unicode/space paths, including content, revisions, inherited directives, ordering, and immediate-child depth.
2. An in-memory source can express diagonal identities, parallel typed off-diagonal relationships, a cycle, and a nested value without objective/path fields or filesystem access. Reading one neighborhood terminates without recursive traversal.
3. Existing 9 repository tests and focused adapter tests pass; typecheck and production build pass. Existing browser acceptance passes if the environment provides Playwright/Chromium; otherwise visual/editing behavior remains unverified and is reported explicitly.
4. Routes, editor, API write handlers, repository authorization/protected-intent logic, dependencies, and founder objectives/directives remain unchanged except the page loader's read boundary.

## Procedure
Inspect implementation and baseline; define a small typed read interface; map the existing repository into entries; project only objective containment into the existing editor; test equivalence and a non-filesystem source; run checks and preserve results.
